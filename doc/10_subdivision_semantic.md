# Семантическое определение подразделений

## Синхронизация справочников

Для загрузки справочников из `portal_db` в кэш приложения выполните:

```bash
python manage.py sync_portal_reference --rebuild-embeddings
```

Синхронизация пересчитывает эмбеддинги автоматически, если подразделение новое,
эмбеддинг отсутствует или изменилось название/алиасы. Для полного принудительного
пересчёта используйте `--rebuild-embeddings`. Если нужно сбросить кэшированные
данные перед синхронизацией, добавьте `--reset`. После обновления логики
сопоставления обязательно выполните:

```bash
python manage.py sync_portal_reference --rebuild-embeddings
python manage.py sync_subdivision_cache --rebuild-embeddings
```

## Поведение и пороги

- Кэш содержит ПУ/подразделения. Таблица `CachedSubdivisionAlias` и поле
  `CachedSubdivision.legacy_aliases` остаются для обратной совместимости, но не
  участвуют в сопоставлении.
- Для поиска используется подстрочное совпадение по `short_name`, затем
  семантическая близость (если модель доступна).
- Если модель недоступна (`SKIP_SEMANTIC_MODEL=1`), используется только
  подстрочное сопоставление.

Пороги уверенности для интерфейса:

- **≥ 0.85** — зелёный индикатор.
- **0.75–0.85** — жёлтый индикатор.
- **< 0.75** — красный индикатор или отсутствие значения.

## Оффлайн-режим

При `SKIP_SEMANTIC_MODEL=1` синхронизация всё равно обновляет справочник, но эмбеддинги
не вычисляются. Это позволяет запускать тесты без загрузки модели.

## Админ-панель (опционально)

В админ-панели доступны модели **Cached PU** и **Cached Subdivision**. Для быстрой
пересборки эмбеддингов есть действие **Rebuild embeddings** в списке подразделений.
